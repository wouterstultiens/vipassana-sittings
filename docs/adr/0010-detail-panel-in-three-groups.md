# The detail panel in three groups: when, join, host

The sitting's detail panel had grown into one run of rows: the time card, then the join and host page buttons side by side, the meeting id, password, dial-in, and contact under them, the listing's text folded away, and at the very bottom a line that said to check the host page before joining. Two kinds of thing were mixed: what an old student needs to attend this one sitting, and what is about the host and the listing in general. We looked at how Google Calendar, Luma, and Meetup lay out an event, and they agree: title, when, how to get in, then the organiser and the description last. We decided on three groups under the title, named in small capitals. **When**: the date, the time range with its length when it is not one hour, where the host's clock is, and the calendar file. **Join**: the join link as the one filled button, and under it the meeting id, password, and dial-in for when the link alone is not enough. **Host**: the host page as an outline button, then the contact and the listing's text as "Host page details". The line about checking the host page is gone: the button under its own heading says as much. A long listing name is cut to one line with an ellipsis, in the panel and in the slot's list alike, with the full name on hover.

## Considered options

- **Keep the join and host page buttons side by side.** Two buttons of equal weight ask the old student to choose; one filled button says what to do, and the host page is a check, not the way in.
- **Keep a note that the host page has the latest word.** Tried under the host page button. The owner found it noise: the host page under its own heading already says where to look.
- **Show the length for every sitting.** "1 h" on every panel is noise; the length is a tag on the row and a note on the panel only when it is not the usual hour.
