Extract the sittings of this host from these texts. For the schedule, a page wins over a row when they disagree; take the whole programme from all texts together, a row often names only part of it. For the join details, every text counts: merge what the texts give for one room. A "leads to" line is information about a url, never a value to copy.

- `name`: a centre gets "Dhamma " and its Pali name in plain letters. A centre's site is its Pali name before .dhamma.org, in the host url, a row url, or a page: talaka.dhamma.org gives "Dhamma Talaka", mahi.dhamma.org "Dhamma Mahi", karuna "Dhamma Karuna". A country code such as lb or fr is not a Pali name. A host that is not a centre gets its country or region in English: "Spain", "Lebanon", "South Korea", "United Arab Emirates"; "Dhamma " never goes before a country or a town. Only a host whose API name is "VDGS <zone> (<US region or India>)" keeps "VDGS " and the region in English: "VDGS US Central", "VDGS India"; no other host gets "VDGS ". Never the API's internal strings.
- `timeZone`: the canonical IANA zone of the host's country and city. Never America/Montreal, Asia/Calcutta, or Europe/Kiev; Asia/Hebron for Palestine.
- `languages`: exactly the rows' event_instruction_languages as codes, in that order, nothing added from a page. When empty: the languages the texts say the sittings are held in, else the language the texts are written in.
- `medium` follows the platforms: `audio` when every join is a phone or audio-only call, `stream` for a live broadcast on a website, else `video`; Zoom, Google Meet, and Teams are video. The API's "Audio-Only", "AV", and "Stream" host names mean nothing.
- `teacherLed` only when a text says an assistant teacher (AT) leads the sittings that have a rule. `questionsAndAnswers` only when a text says those sittings have a Q&A. Not from a guideline, a login note, or a sitting without a rule.
- `pageUrl`: the page with the schedule; for a host on a shared page, the host's own site the page names; else a row url or host url with status 200 that is a web page, not a meeting, written as the url it lands on, a site root too. Null when none.
- Only the sittings this host holds. A page's sittings of another centre or region are not this host's. When a shared page gives one room per host, a host gets only the sittings of its room. Two hosts of one centre split the page: each gets the sittings its rows name.
- A sitting that needs registration or a form, or has no fixed weekday, gets no rule. A sitting whose link is only on a calendar behind the page keeps its rule, with `url` null and the platform the page names.
- One rule per sitting. A block of consecutive parts, chanting, sitting, discourse, is one sitting from the first start to the last end. Duration: the end the text gives minus the start; "1hr" is 60 even with a Q&A after; one hour when nothing is given. When a special sitting replaces the regular one on some weeks of the month, the regular rule gets the other numbered weeks, never -1 with them.
- The join details in a text belong to every sitting in that text unless the text names a room for a sitting. A table with one room: every cell of join detail belongs to every sitting in the table, whatever line it stands on. The link and the dial-in of one room are one join.
- `join.url`: the url as the row or page writes it, never a url from a "leads to" line; a url in brackets after a link text is the real one, and a url never ends with ]. An Outlook safelink is unwrapped to the url inside it. When the texts give two urls for one room, keep the one that carries the password. Never shorten a url.
- `label`: null for a group sitting, whatever the host calls it. Otherwise the host's own short words for a half-day, a one-day, a sitting with a discourse, or a named room: "Half-day", "1-Day Program", "Virtual 1".
- `password`: `given` with the value exactly as a text writes it, "behappy" is always lower case; `old-student` only when a text says the meeting takes the usual old-student password, a website login note is not that; else `none`. The `pwd` or `p` parameter of a url is not a password.
- `meetingId`: the digits of the id, with spaces between groups. Zoom: 3-3-3 for 9 digits "445 316 575", 3-3-4 for 10 "994 070 9389", 3-4-4 for 11 "858 5275 0934". Teams: groups of three "359 652 939 515". Google Meet: the digits the text gives; a Meet code of letters is part of the url, not an id. Null for a phone-only platform, where the code is the `accessCode`.
- `dialIn` only when a text says to dial in or join by phone; numbers to call when you have a problem are not dial-in. Numbers exactly as written, nothing added, without the country label; a one-tap string gives neither a number nor a code. `accessCode`: the numeric passcode written for the phone, without #; for Zoom the PW after the dial number, never the meeting id; else null.
